# アイドル・エコシステム会議

アイドル領域における複数リポジトリ・研究・データ・公開面を横断して、役割分担と次のアクションを決めるための会議体。

## 目的

`idol-portal` を入口として、アイドル関連リポジトリを一つの巨大なリポジトリへ戻すのではなく、**疎結合なエコシステムとして連携**させる。

特に、理論研究・個別ケース研究・観測・アーカイブ・UIを分離し、それぞれの成果を相互参照できる状態を維持する。

## 現在の構成

| Repository | 役割 |
|---|---|
| `idol-portal` | エコシステム入口・会議・ナビゲーション |
| `idol-lab` | アイドル民俗学・理論・オントロジー |
| `idol-fansite` | 個別アイドルの公開・観測面 |
| `idol-live` | ライブ情報・イベント観測 |
| `idol-map` | アイドル／地域情報 |
| `idol-banduke` | ランキング・評価データ |
| `idol-oshare` | アイドル文化・ファッション関連 |
| `idol-produce` | アイドルプロデュース実験 |
| `idol-quiz` | クイズ・学習UI（`idol-lab` へ統合済み） |

## テラスマ研究

`idol-lab` が肥大化しないよう、特定グループを対象としたケース研究は別リポジトリへ分離する。

```text
idol-lab
  └─ 一般理論・方法論

terasuma-lab
  └─ テラスマのケース研究

idol-fansite
  └─ 観測・公開
```

### テラスマ研究の基本ループ

```text
観測
 ↓
問い
 ↓
仮説
 ↓
予測
 ↓
調査・証拠収集
 ↓
検証
 ├─ 支持
 ├─ 反証
 └─ 不確定
 ↓
解釈
 ↓
次の問い
 ↺
```

## マーケティング・リサーチ

個別ケース研究では、文化研究だけでなくマーケティングの分析手法も利用する。

```text
市場
 ↓
セグメント
 ↓
接触
 ↓
興味
 ↓
初回体験
 ↓
ファン化
 ↓
継続
 ↓
推薦
```

分析対象には以下を含める。

- 認知経路
- タッチポイント
- ファン・ジャーニー
- ポジショニング
- 差別化要因
- メンバーごとの役割
- ライブ／SNS／メディアの相互作用
- お笑いとアイドル活動の相互作用

## エージェント構想

マーケティング・リサーチと文化研究を複数エージェントに分担させる。

```text
Scout Agent
  ↓
Evidence Agent
  ↓
Marketing Analyst ──┐
Cultural Analyst ───┼→ Synthesis Agent
Fan Researcher ────┘        ↓
                         Next Question
                              ↓
                         Research Agent
                              ↺
```

エージェント実装はフレームワークに固定せず、研究データと状態をGitHub上のMarkdown/YAML/JSONで保持する。

## 会議で決めること

1. 各リポジトリの責務
2. リポジトリ間のデータ連携
3. 共通ID・参照方法
4. 研究仮説と検証方法
5. 観測データの出典・provenance
6. 次に作るべきIssue / Repository
7. エージェントに委譲できる作業

## 原則

- 研究とファン活動を混同しない
- 観測事実・解釈・仮説を分離する
- 出典を残す
- 個別ケース研究を `idol-lab` に再集積しない
- リポジトリは責務単位で小さく保つ
- `idol-portal` は司令塔ではなく、エコシステムの入口・会議面とする
- 新しい研究は既存研究から次の問いを生成する
